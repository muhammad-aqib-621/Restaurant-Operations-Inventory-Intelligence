# Implementation contract (current coding coordination)

All API paths below are mounted under `/api`. Success responses `{data: result}`, list responses `{data: rows, pagination:{page,pageSize,total}}`; errors `{error:{code,message,requestId}}`. Zod validates every write. Decimal money/quantities enter as strings; serialize Prisma Decimals as strings. IDs are cuid strings. Backend feature modules export Express routers named `catalogRouter`, `inventoryRouter`, `ordersRouter`, `purchasingRouter`, `reportsRouter`. Do not edit another feature's files without coordinating.

## Shared backend helpers (owned by main agent)

Import from `../lib/core.js`: `prisma`, `Decimal` (Prisma.Decimal class), `AppError(status,code,message)`, `requireRoles(...roles)` Express middleware, `tx(fn)` serializable transaction with conflict retry, `idempotent(transaction, actorId, scope, key, payload, operation)` returning cached/result JSON atomically, `requestKey(req)` validates Idempotency-Key, `audit(transaction, actorId, action, entityType, entityId, details?)`, `notify(transaction, type,title,message,roles:Role[])`, `publish(event,payload,roles?:Role[])`, `quantity(value,fromUnit,canonicalUnit)` explicit compatible conversion returning Decimal, `pagination(req)` returning {page,pageSize,skip,take}. `tx` transaction type is Prisma.TransactionClient. `req.user` is authenticated `{id,name,email,role,active}`. All routers require authentication globally except auth and foundation endpoints. Every route must enforce role authorization. Roles are OWNER MANAGER CASHIER KITCHEN INVENTORY. `audit` and stock/financial mutations must share the business transaction. `publish` only after commit. Decimal inputs use `z.string().regex(...)`; never accept browser totals.

## Prisma model contract

Schema agent owns schema, migrations, and seed. Fields listed are exact names. Add inverse relations as necessary. All models have `id String @id @default(cuid())` and `createdAt @default(now()) @db.Timestamptz(3)` except composite rows, Session, RestaurantSettings. Money Decimal(14,2), quantities Decimal(18,6), unitCost Decimal(18,6). Enumerations: Role above; Unit G KG ML L PIECE; OrderStatus PENDING CONFIRMED PREPARING READY COMPLETED CANCELLED; PurchaseStatus DRAFT ORDERED PARTIAL RECEIVED CANCELLED; MovementType OPENING PURCHASE CONSUMPTION WASTE ADJUSTMENT COUNT REVERSAL; ReservationStatus ACTIVE CONSUMED RELEASED; ApprovalStatus PENDING APPROVED REJECTED; PaymentType PAYMENT REFUND.

- User: name,email(unique lowercased),passwordHash,role,active(defaulttrue),updatedAt. Never return passwordHash.
- Session: sid String primary varchar, sess Json, expire timestamptz; table name Session (connect-pg-simple tableName).
- RestaurantSettings: existing singleton fields plus cashierDiscountLimit Decimal(7,6) default0.05, paymentMethods String[] default [CASH,CARD,BANK_TRANSFER].
- Supplier: name,contactName?,email?,phone?,address?,active true,updatedAt. `ingredients`, `purchaseOrders` relations.
- Ingredient: name,sku unique,category String,unit Unit(canonical only G/ML/PIECE),onHand Decimal default0,reserved Decimal default0,minimumStock Decimal default0,unitCost Decimal default0,preferredSupplierId?,expiresAt?,storageNotes?,active true,updatedAt. `preferredSupplier`, `movements`, `reservations` relations.
- MenuCategory: name unique,sortOrder Int default0,active true; `items`.
- MenuItem: categoryId,name,description?,imageUrl?,price Decimal,active true,updatedAt; `category`, `recipe` optional, `orderItems`.
- Recipe: menuItemId unique; `menuItem`, `versions`.
- RecipeVersion: recipeId,version Int,createdById; `recipe`, `createdBy`, `ingredients`; unique(recipeId,version).
- RecipeIngredient: id,recipeVersionId,ingredientId,quantity Decimal(canonical); `ingredient`, `recipeVersion`; unique(recipeVersionId,ingredientId). No createdAt needed.
- Customer: name,phone?,email?; `orders`.
- Order: number Int unique autoincrement,status OrderStatus defaultPENDING,customerId?,notes?,subtotal,discount,tax,total,estimatedCost all Decimal default0,createdById,updatedAt; `items`,`payments`,`reservations`,`customer`,`createdBy`.
- OrderItem: orderId,menuItemId,recipeVersionId,name String(price snapshot label),quantity Int,unitPrice Decimal,estimatedUnitCost Decimal,notes?,preparedQuantity Int default0; `order`,`menuItem`,`recipeVersion`. No createdAt needed.
- Payment: orderId,type PaymentType defaultPAYMENT,amount Decimal,method String,reference?,createdById; `order`,`createdBy`. Refunds are positive amounts typed REFUND. No real payment gateway is claimed.
- InventoryReservation: orderId,ingredientId,quantity Decimal,status defaultACTIVE; `order`,`ingredient`; unique(orderId,ingredientId).
- InventoryMovement: ingredientId,type MovementType,quantity Decimal(signed),unitCost Decimal,reason String,reference String?,actorId,orderId?,goodsReceiptId?,reversalOfId? unique; `ingredient`,`actor`,`order`,`goodsReceipt`,`reversalOf` self and inverse. Append-only DB trigger forbids update/delete. No direct balance edits without movements.
- PurchaseOrder: number Int unique autoincrement,supplierId,status PurchaseStatus defaultDRAFT,expectedAt?,notes?,createdById,updatedAt; `supplier`,`items`,`receipts`,`createdBy`.
- PurchaseOrderItem: purchaseOrderId,ingredientId,quantity Decimal,receivedQuantity Decimal default0,unitCost Decimal; `ingredient`,`purchaseOrder`,`receiptItems`; unique(purchaseOrderId,ingredientId). No createdAt needed.
- GoodsReceipt: purchaseOrderId,invoiceReference?,receivedById; `purchaseOrder`,`items`,`receivedBy`,`movements`.
- GoodsReceiptItem: goodsReceiptId,purchaseOrderItemId,quantity Decimal,unitCost Decimal,expiresAt?; `goodsReceipt`,`purchaseOrderItem`. No createdAt needed.
- WasteRecord: ingredientId,quantity Decimal,reason,estimatedCost Decimal,status ApprovalStatus defaultPENDING,createdById,approvedById?,approvedAt?; `ingredient`,`createdBy`,`approvedBy`.
- StockAdjustment: ingredientId,quantity Decimal(signed delta),reason,status ApprovalStatus defaultPENDING,createdById,approvedById?,approvedAt?; relations as waste.
- StockCount: notes?,status ApprovalStatus defaultPENDING,createdById,approvedById?,approvedAt?; `items`,`createdBy`,`approvedBy`.
- StockCountItem: stockCountId,ingredientId,expectedQuantity Decimal,countedQuantity Decimal; `stockCount`,`ingredient`; unique(stockCountId,ingredientId). No createdAt needed.
- IdempotencyRecord: actorId,scope,key,requestHash,response Json; unique(actorId,scope,key). No user relation needed.
- Notification: type,title,message,roles Role[],userId?; `reads`. NotificationRead: notificationId,userId,readAt defaultnow composite primary key. Filter notifications by roles/user, never leak to other roles.
- AuditLog: actorId?,action,entityType,entityId?,details Json?; `actor`. Append-only, no secrets.

Database checks: onHand>=0,reserved>=0,reserved<=onHand,minimumStock/unitCost>=0, canonical ingredient units; prices>=0, recipe qty>0, order qty>0, preparedQty within quantity, reservation qty>0; tax/discount fractions in[0,1]; purchase received between0 andordered. Preserve existing initial migration. New migration uses Prisma diff/create SQL plus manual checks/history triggers. Seed development-only idempotent, random/provided development password (never hardcoded production password). Seed owner/manager/cashier/kitchen/inventory using emails owner@newkarachi.test etc, env DEMO_PASSWORD required from ignored local .env. Seed realistic catalog/recipes/stock via immutable OPENING ledger, supplier, and sample history only if explicitly labelled demo; do not overwrite existing data.

## Routes and payloads

Auth (main): GET /auth/me -> {user:null|safeUser,csrfToken}; POST /auth/login {email,password} -> {user,csrfToken}; POST /auth/logout. GET/POST /users, PATCH /users/:id. GET/PATCH /settings. All writes require x-csrf-token; browser helper manages token. Backend checks active user on each request. Sessions persist in PostgreSQL; bcrypt12 passwords; production secure cookie. Readiness existing stays public with only nonsensitive config.

Catalog/inventory: GET/POST/PATCH /categories(/:id); GET/POST/PATCH /menu(/:id); POST /menu/:id/recipes {ingredients:[{ingredientId,quantity,unit}]} creates immutable version, GET /menu/:id/recipes. GET/POST/PATCH /ingredients(/:id), no direct onHand/reserved patch. List menu includes category, recipe.versions[0].ingredients.ingredient, estimatedCost/margin/available if practical. GET /inventory/movements filters ingredientId/type/from/to/page; GET /inventory/alerts; GET /inventory/reservations; GET/POST /inventory/counts {notes?,items:[{ingredientId,quantity,unit}]} and POST /inventory/counts/:id/approve; GET/POST /inventory/adjustments {ingredientId,quantity(signed),unit,reason}, POST /inventory/adjustments/:id/approve; POST /inventory/movements/:id/reverse {reason} OWNER only (restrict to adjustment/count, one compensation). Writes manager/owner; inventory may submit counts/adjustments, only manager/owner approve. Approvals fail if availability insufficient or stale count snapshot. Forecast estimate using recent consumption, insufficient-history explicit.

Orders: GET /orders filters status/from/to/page (all ops roles except INVENTORY), GET /orders/:id, POST /orders {items:[{menuItemId,quantity,notes?}],notes?,discount?:decimal amount,customer?:{name,phone?},confirm?:boolean}; cashier/manager/owner. POST /orders/:id/status {status}; kitchen/manager/owner progress, cashier complete/cancel pending only; transition validation. POST /orders/:id/items/:itemId/ready {quantity:int} kitchen/manager/owner. POST /orders/:id/payments {amount:string,method,reference?}; POST /orders/:id/refunds {amount,method,reference?,reason} owner/manager. GET /orders/:id/receipt read JSON printable data. All command POSTs require idempotency header; payload reuse with different contents409. Confirmation reserves latest-at-creation recipe version snapshots; PREPARING consumes once, cancellation before prep releases reservations. Cancellation after prep owner/manager only, no auto-restock. Completed requires fully paid. Order READY after all items prepared. Payments validate outstanding balance and configured method; refund never exceeds net captured. Emit orders:changed/inventory:changed only after commit.

Purchasing/reports: GET/POST/PATCH /suppliers(/:id) manager/owner, inventory canGET; GET/POST /purchases {supplierId,expectedAt?,notes?,items:[{ingredientId,quantity,unit,unitCost}]} -> DRAFT; POST /purchases/:id/status {status:ORDERED|CANCELLED}; POST /purchases/:id/receipts {invoiceReference?,items:[{purchaseOrderItemId,quantity,unit,unitCost,expiresAt?}]} allows partial actual receipt, no overreceive/duplicates, update weighted-average ingredientunitcost and ledgertransactionally; receivinginventoryallowed. GET /waste, POST /waste {ingredientId,quantity,unit,reason}, POST /waste/:id/approve manager/owner. GET /reports/dashboard, GET /reports/:type (sales,items,hourly,consumption,valuation,movements,waste,purchases,reorder), /reports/:type?format=csv; date filters from/to YYYY-MM-DD interpreted Asia/Karachi configuredtime zone, inclusive business dates -> exclusiveUTCend. Dashboard real DB aggregates sales(excluding tax),tax,collected/refunds,orderCount,averageOrderValue,estimatedCogs,grossProfit,lowStockCount,pendingPurchases,wasteCost,bestSellers,salesSeries,recentOrders. OWNER/MANAGER reports only. GET /audit owneronly (main); GET /notifications and POST /notifications/:id/read authorized broadcast scope (main).
